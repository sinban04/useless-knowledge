SCoP란 — 폴리헤드럴 분석이 적용되는 코드 영역

SCoP(Static Control Part, 정적 제어 영역)는 폴리헤드럴 모델로 정확히 분석·변환할 수 있는 코드의 최대 영역이다. 직관적으로는 "제어 흐름과 메모리 접근이 컴파일 타임에 전부 affine(1차)으로 결정되는 중첩 루프 덩어리"다 [4][6].

핵심은 정적(static) 이라는 말에 있다. 루프를 몇 번 도는지, 어떤 배열 칸을 건드리는지, 어떤 분기를 타는지가 — 실행해 보지 않아도 루프 인덱스와 컴파일 타임 파라미터의 1차식만으로 결정되어야 한다. 그래야 반복 공간을 정수 다면체(polyhedron)로 적고, 의존성을 정수 부등식으로 정확히(exact) 풀 수 있다 [6].

무엇이 SCoP를 만드는가 — 세 가지 affine 조건

중첩 루프가 SCoP이려면 다음 셋이 모두 루프 인덱스 벡터 $\mathbf{i}$ 와 파라미터 $\mathbf{N}$ 의 affine 식(계수의 곱·합·상수만)이어야 한다 [4][6]:

  1. 모든 루프 경계 (lower/upper bound) — 예: for i = 1 to N-1은 OK, for i = 1 to f(i)는 불가.
  2. 모든 배열 첨자 (array subscript) — 예: A[i+j-1]은 OK, A[i*j]·A[B[i]]는 불가.
  3. 모든 분기 조건 (if) — 예: if (i + 2*j <= N)은 OK, if (A[i] > 0)(데이터 의존)은 불가.

그리고 영역 안에서 부수효과·포인터 alias·함수 호출이 분석을 깨지 않아야 한다(순수한 배열 read/write만). 이 조건들이 만족되면 경계 부등식을 모아 반복 공간

$$D = \{\, \mathbf{i} \in \mathbb{Z}^n \ :\ A\,\mathbf{i} + \mathbf{b} \ge \mathbf{0} \,\}$$

이라는 정수 다면체를 얻는다. 각 정수격자점이 루프 본문의 한 실행 인스턴스다.

SCoP에서 추출하는 5객체

한 SCoP가 확정되면, 폴리헤드럴 표현은 다섯 가지 객체로 코드를 완전히 기술한다 [4][6]:

#객체무엇수식
1반복 공간 (iteration domain)어떤 인스턴스들이 도는가$D=\{\mathbf{i}: A\mathbf{i}+\mathbf{b}\ge\mathbf{0}\}$
2접근 함수 (access function)각 인스턴스가 건드리는 메모리 칸$F(\mathbf{i})=A_F\mathbf{i}+\mathbf{f}$
3의존성 (dependences)어떤 인스턴스가 어떤 인스턴스에 묶이나$\delta=\mathbf{i}'-\mathbf{i}$
4스케줄 (schedule)인스턴스의 논리적 실행 시각$\theta(\mathbf{i})=\Theta\mathbf{i}$
5파라미터/문맥 (context)컴파일 타임 상수의 제약$N\ge 1$ 등

①②③은 코드에서 읽어 들이는 사실이고, ④ 스케줄만이 우리가 바꿀 수 있는 자유도다 — 폴리헤드럴 최적화 = 합법적인 $\Theta$ 를 찾는 일이다(합법성 판정에는 Farkas Lemma가 쓰인다).

SCoP vs 비-SCoP — 경계 예시

// ✅ SCoP — 경계·첨자·조건이 모두 affine
for (i = 1; i < N-1; i++)
  for (j = 1; j < N-1; j++)
    A[i][j] = A[i-1][j] + A[i][j-1];

// ❌ 비-SCoP — 비선형/간접/데이터 의존
for (i = 0; i < N; i++)
  for (j = 0; j < i*i; j++)     // 경계가 i*i (비선형)
    A[B[i]][j] = C[i] / A[i][j]; // 첨자 B[i] (간접), 0-나눗셈 가능
패턴SCoP?이유
for i=0..N, A[2*i+1]✅경계·첨자 affine
A[i*j]❌첨자 비선형 (두 인덱스의 곱)
A[B[i]]❌간접 접근 (데이터 의존 첨자)
while (p != null)❌반복 횟수가 정적이지 않음
if (A[i] > 0)❌분기가 데이터에 의존
if (i + j <= N)✅분기가 affine

비-SCoP 코드도 컴파일은 되지만, 컴파일러는 "혹시 겹칠지 모른다"는 보수적 가정으로 후퇴해 타일링·병렬화 같은 공격적 변환을 포기한다. SCoP는 그 포기 없이 정확히 푸는 영역이다.

MLIR은 SCoP를 IR 문법으로 강제한다

폴리헤드럴 컴파일러(Pluto, Polly 등)는 일반 IR/소스에서 SCoP를 탐지(detect) 해야 한다 [4][5]. MLIR의 affine dialect는 발상을 뒤집는다 — affine.for·affine.if·affine.load/store는 문법적으로 affine 식만 받도록 제한되어 있어, "affine dialect에 들어와 있다 = 이미 SCoP 안에 있다"가 성립한다 [8]. 즉 SCoP가 사후 분석 결과가 아니라 IR 타입 수준의 보장이다.

  • affine.for %i = 0 to affine_map<()[s0]->(s0)>()[%N] — 경계가 affine map
  • affine.if affine_set<(d0,d1) : (d0 + d1 - 1 >= 0)> — 조건이 integer set(다면체)
  • affine.load %A[%i + %j - 1] — 첨자가 affine

이 제약 덕분에 affine-loop-tile·affine-loop-fusion 같은 변환이 다면체 위에서 안전하게 동작한다. 반대로 첨자에 arith.muli로 만든 비-affine 인덱스를 쓰면 verifier가 거부한다 — IR이 SCoP를 벗어나지 못하게 막는 셈이다.

한눈 요약

  • SCoP = 경계·첨자·분기가 모두 affine한, 폴리헤드럴로 정확히 분석되는 최대 코드 영역.
  • 만족 조건 셋(affine 경계·affine 첨자·affine 분기 + 부수효과 없음) → 반복 공간 다면체 → 5객체 추출.
  • 5객체 중 스케줄 $\Theta$ 만이 바꿀 수 있는 자유도, 그 합법성은 Farkas Lemma로 유한 검사.
  • MLIR affine dialect는 SCoP를 탐지가 아니라 문법으로 강제 — 그래서 affine = "분석 가능 영역".
